# 질문 기차 게임 · 구글 시트 버전

「질문하는 힘 기르기」 1차시용 모둠 대결 웹앱의 **구글 시트(Apps Script) 버전**이에요.
모둠마다 태블릿 한 대를 두고, 모둠원이 차례대로 태블릿을 넘기며 질문을 하나씩 써서 기차 칸을 이어 붙여요.
다른 모둠 기차는 **터널 속**에 숨어 있어서 길이를 볼 수 없고, 시간이 끝나면 선생님 화면에서 **두구두구 순위 발표**와 함께 모든 질문이 공개돼요.

- 화면은 **노트북과 태블릿**(가로·세로)에 맞춰 만들었어요. 휴대폰은 고려하지 않았어요.
- 빌드 도구 없이 동작하는 정적 웹사이트(HTML·CSS·JavaScript)예요. GitHub Pages에 올리면 바로 쓸 수 있어요.

## 세 가지 수업 방식

| 수업 방식 | 누가 준비하나요 | 선생님이 할 일 | 질문 기록 |
| --- | --- | --- | --- |
| **체험 서버** | 개발진이 한 번 배포 | 없음 (바로 게임 만들기) | 개발진 체험 서버 시트, **24시간 뒤 자동 삭제** |
| **내 구글 시트** | 선생님이 사본 만들기 | 사본 만들기 → 웹 앱 배포 → 주소 붙여 넣기 (10분) | **선생님 시트에 계속 남음** |
| **연습 모드** | 필요 없음 | 없음 | 이 브라우저 안 (한 컴퓨터의 여러 창에서만) |

- 체험 서버는 연수·시범 수업에서 "일단 해 보기"용이에요. 여러 학교가 함께 쓰니, 모둠 친구 이름은 **실명 대신 번호나 별명**을 쓰도록 태블릿 화면에서 안내해요.
- 우리 반 정식 수업은 **내 구글 시트**를 권해요. 학생 질문이 선생님 시트의 '질문 기록' 탭에 쌓여서 다음 차시에 그대로 쓸 수 있어요.
- 세 방식 모두 **같은 서버 코드(`gas/Code.gs`)**를 써요. 연습 모드도 이 코드를 브라우저 안에서 그대로 돌려서, 연습 모드에서 되는 일은 구글 시트에서도 똑같이 돼요.

## Firebase 버전과 다른 점

| | Firebase 버전 (`question-train-game`) | 구글 시트 버전 (이 폴더) |
| --- | --- | --- |
| 기기 | 학생 한 명에 한 대 | **모둠에 한 대** (돌려쓰기) |
| 차례 넘기기 | 서버를 거쳐 실시간 | 태블릿 안에서 바로 |
| 다른 모둠 기차 길이 | 실시간으로 보임 | 터널 속에 숨김 → 끝나고 순위 발표 |
| 선생님 진행 화면 | 모둠별 기차가 자라는 전광판 | 터널 속을 달리는 기차, 태블릿 연결 상태 |
| 질문이 쌓이는 곳 | Firebase (7일 뒤 자동 삭제) | 선생님 구글 시트 / 체험 서버(24시간) |

사진·시간·모둠 수·겹치는 질문 판정·효과음(시작 종, 마지막 5초 삐 소리, 끝 종)·결과 화면·CSV 내려받기·한 판 더는 두 버전이 같아요.

## 개발진이 할 일 (처음 한 번)

### ① 체험 서버 만들기

1. 개발진 개인 Gmail로 새 구글 시트를 만들어요. 이름 예: **질문 기차 체험 서버**
2. **확장 프로그램 → Apps Script** → 프로젝트 이름을 **질문 기차 서버**로 바꾸고, 원래 코드를 지운 뒤 `gas/Code.gs`를 붙여 넣고 저장해요.
3. 함수 칸에서 **setupTrialServer**를 골라 **▷ 실행** → 권한 허용 ("Google에서 확인하지 않은 앱" → 고급 → 이동 → 허용)
4. **배포 → 새 배포 → 웹 앱** (실행: 나 / 액세스 권한: **모든 사용자**) → 배포 → 웹 앱 URL(`…/exec`) 복사

### ② 사본용 원본 시트 만들기 (체험 서버와 **다른** 시트)

1. 새 구글 시트를 하나 더 만들어요. 이름 예: **질문 기차 게임 (사본용)**
2. ①-2처럼 Apps Script에 `gas/Code.gs`를 붙여 넣고 프로젝트 이름을 **질문 기차 서버**로 바꿔요.
3. 함수 칸에서 **setupTemplate**를 골라 **▷ 실행** → '처음 안내', '질문 기록', '사진 저장소' 탭이 생겨요.
4. 이 시트는 **배포하지 않아요.** 오른쪽 위 **공유 → 일반 액세스: 링크가 있는 모든 사용자 · 뷰어**로 바꾸고 링크를 복사해요.
5. 링크의 `/edit…` 부분을 `/copy`로 바꿔요. 예: `https://docs.google.com/spreadsheets/d/1AbC…/copy`

> 체험 서버 시트를 사본용으로 쓰면 안 돼요. 다른 학교 질문 기록과 체험 서버 설정까지 함께 복사돼요.
> 사본용 원본은 배포하거나 선생님 설정에 연결해 보지 마세요. 해 봤다면 사본을 공유하기 전에 **setupTemplate**를 한 번 더 실행해 남은 비밀번호와 게임 정보를 비워 주세요.

### ③ 게임 사이트에 두 주소 넣기

GitHub 저장소에서 `js/config.js`를 열고 연필(✏️) 버튼을 눌러 두 줄을 고친 뒤 **Commit changes**를 눌러요.

```js
export const TRIAL_GAS_URL = 'https://script.google.com/macros/s/……/exec';        // ①에서 복사한 웹 앱 주소
export const TEMPLATE_COPY_URL = 'https://docs.google.com/spreadsheets/d/……/copy'; // ②에서 만든 사본 주소
```

1~2분 뒤 사이트를 새로고침하면, 선생님 화면에 **체험 서버**가 생기고 선생님 설정에 **사본 만들기** 버튼이 생겨요.
두 주소를 비워 두면 체험 서버는 숨겨지고, 설정 화면은 "직접 만들기(코드 붙여 넣기)" 안내로 바뀌어요.

### 코드를 고쳐서 다시 올릴 때

- **체험 서버**: 편집기에 새 코드를 붙여 넣고 저장 → **배포 → 배포 관리 → 연필(수정) → 버전: 새 버전 → 배포** (주소가 바뀌지 않아요. 체험 서버 설정도 그대로 남아요)
- **사본용 원본**: 새 코드를 붙여 넣고 저장만 하면 돼요. 앞으로 사본을 만드는 선생님부터 새 코드를 받아요. 이미 사본을 만든 선생님은 선생님 설정의 "직접 만들기"에서 코드를 복사해 자기 편집기에 붙여 넣고 새 버전으로 배포하면 돼요.

## 선생님이 할 일

- **체험 서버**: 게임 사이트 → 선생님용 → 수업 방식 **체험 서버** → 게임 코드 만들기. 끝!
- **내 구글 시트**: 게임 사이트 → **선생님 설정**에 나온 3단계
  1. **사본 만들기** 버튼 → 내 드라이브에 서버 코드가 들어 있는 시트가 복사돼요.
  2. 복사된 시트에서 **확장 프로그램 → Apps Script → 배포 → 새 배포 → 웹 앱** (실행: 나 / 액세스: 모든 사용자) → 액세스 승인 → 웹 앱 URL 복사
  3. 선생님 설정에 웹 앱 URL을 붙여 넣고 **선생님 비밀번호**를 정해요.

모둠 태블릿은 선생님 대기실 화면의 **QR 코드**(또는 "입장 링크 복사")로 들어와요. 링크에 서버 주소가 담겨 있어서, 한 번 들어온 태블릿은 다음부터 코드만 입력해도 돼요.

| --- | --- |
| `index.html` | 처음 화면: 선생님용 / 학생용(모둠 태블릿) 고르기 |
| `teacher.html` | 선생님: 게임 만들기(수업 방식 3가지) → 대기실(코드·QR) → 진행(터널) → 도착 확인 → 두구두구 순위 발표 → 결과 |
| `student.html` | 모둠 태블릿: 코드 입력 → 모둠 고르기 → 친구 이름·차례 정하기 → 대기 → 게임(돌려쓰기) → 도착 → 결과 |
| `setup.html` | 선생님 설정: 사본 만들기 → 배포 → 주소 붙여 넣기 (사본이 안 될 때 직접 만들기) |

## 바로 써 보기 (내 컴퓨터)

ES 모듈을 쓰기 때문에 파일을 더블클릭(`file://`)하면 동작하지 않아요. 간단한 웹 서버로 열어 주세요.

```bash
cd question-train-game-sheet
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000 열기
```

VS Code를 쓴다면 Live Server 확장으로 `index.html`을 열어도 돼요.

연습 모드 체험 순서:
1. `선생님용` → 수업 방식 **연습 모드** → 사진·시간·모둠 수 정하기 → **게임 코드 만들기**
2. 대기실의 **모둠 태블릿 창 열기**를 여러 번 눌러 창을 띄우고, 각 창에서 모둠을 고르고 친구 이름을 차례대로 쓰기
3. 선생님 창에서 **게임 시작!** → 5초 뒤 모든 태블릿이 함께 출발
4. 시간이 끝나면 태블릿이 기차를 보내고, 선생님 창에서 **두구두구 순위 발표!**

## GitHub Pages로 배포하기

1. GitHub에 새 저장소를 만들어요. 예: `question-train-game-sheet` (Public)
2. 이 폴더 **안의** 파일과 폴더를 모두 올려요(`.nojekyll` 포함, `index.html`이 맨 위에 보이게).
3. 저장소 **Settings → Pages**에서 Branch를 `main` / `(root)`로 정하고 저장해요.
4. 1~2분 뒤 `https://<GitHub 아이디>.github.io/question-train-game-sheet/` 주소로 열려요.
5. 개발진 할 일 ③처럼 `js/config.js`에 체험 서버 주소와 사본 주소를 넣어요.

## 폴더 구조

```
question-train-game-sheet/
├─ index.html, teacher.html, student.html, setup.html
├─ gas/Code.gs                ← Apps Script 서버 코드 (체험 서버·내 구글 시트·연습 모드 공통)
├─ css/app.css                ← 색·글꼴·모양 (Firebase 버전과 같은 디자인 + 터널·순위 발표 화면)
├─ js/
│  ├─ config.js               ← ★ 개발진이 채우는 곳: 체험 서버 주소, 사본 만들기 주소, 상태 확인 간격
│  ├─ teacher.js, student.js, setup.js   ← 화면
│  ├─ api.js                  ← 서버와 이야기하기 (웹 앱 호출, 선생님 열쇠, 연습 모드, 시계 맞추기, 오류 안내)
│  ├─ gas-stub.js             ← 연습 모드에서 Apps Script 서비스(속성·캐시·시트)를 흉내 내는 코드
│  ├─ game.js                 ← 규칙(겹치는 질문 판정, 순위, 예시 사진 목록)
│  ├─ effects.js              ← 효과음과 화면 효과 (시작 종, 마지막 5초, 끝 종, 두구두구, 팡파르)
│  └─ ui.js                   ← 그림(SVG), 알림, 확인창, QR, 이미지 압축
├─ assets/fonts               ← 학교안심 둥근미소 (웹용 WOFF2, 한글 2,350자)
├─ assets/photos              ← 예시 사진 3장
└─ vendor/qrcode.mjs          ← QR 코드 생성기
```

## 게임 규칙 (코드에 반영된 내용)

- 모둠 태블릿에서 친구 이름을 위에서부터 차례대로 써요(8명까지). 화살표로 순서를 바꾸거나 **차례 섞기**를 할 수 있어요. 대기 중에는 이름·차례를 고칠 수 있어요.
- 한 모둠에는 태블릿 한 대만 들어갈 수 있어요. 선생님이 대기실에서 모둠 카드를 눌러 **연결 풀기**를 할 수 있어요.
- 선생님이 시작을 누르면 **5초 뒤** 모든 태블릿이 같은 순간에 출발해요(종소리). 잠깐 멈춤 뒤 다시 출발할 때는 4.5초 준비 시간이 있어요.
- 칸을 붙이면 "다음은 ○○ 차례! 태블릿을 넘겨 주세요"가 크게 떠요. 패스도 할 수 있어요.
- 물음표가 없으면 자동으로 붙여요. 두 글자 미만이나 심한 말은 막아요.
- 겹치는 질문 판정은 같은 모둠 기차 안에서만 해요. **똑같은 질문만 막기(기본)** / **비슷한 질문도 막기** 중에 골라요.
- 마지막 5초는 삐 소리와 큰 숫자, 시간이 끝나면 종소리가 나요. 선생님 화면은 소리가 켜져 있고, 태블릿은 꺼진 채로 시작해요.
- 시간이 끝나면 각 태블릿이 자기 기차를 서버로 보내요. 인터넷이 잠깐 끊겨도 3초마다 다시 보내요. 선생님 화면에서 도착한 기차를 확인하고 **두구두구 순위 발표!**를 눌러요.
- 결과 화면에서 CSV 내려받기, 부적절한 칸 지우기(시트에서도 지워짐), 같은 모둠으로 한 판 더를 할 수 있어요.
- 태블릿을 새로고침하거나 껐다 켜도 붙인 칸과 차례가 그대로 이어져요.

## 체험 서버 규칙

- 선생님 브라우저마다 자동으로 **선생님 열쇠**가 만들어져요. 그 브라우저에서 만든 게임만 보고, 시작하고, 지울 수 있어요. (다른 컴퓨터에서는 관리할 수 없어요)
- 선생님 한 명(브라우저 하나)당 게임 **6개**까지, 체험 서버 전체에 **150개**까지 만들 수 있어요.
- 게임과 질문 기록, 올린 사진은 **24시간 뒤** 모두 지워져요. 결과 화면에서 CSV로 내려받아 둘 수 있어요.
- 체험 서버 시트 주소는 선생님들에게 알려 주지 않아요. 체험 서버 주소를 '내 구글 시트'로 연결하려 하면 막아요.
- 규칙을 바꾸려면 `gas/Code.gs`의 `TRIAL_TTL_MS`, `TRIAL_LIMIT`과 `js/config.js`의 `TRIAL_RULES`를 함께 고쳐요.

## 개인정보와 보안

- 저장하는 정보는 **모둠 번호, 친구 이름(8글자 이내), 질문**뿐이에요. 학생 로그인은 없어요.
- 다른 모둠 질문은 게임 중에 각 태블릿 안에만 있어서 서로 볼 수 없고, 선생님이 순위를 발표한 뒤에만 서버가 내려줘요.
- 선생님 기능은 **선생님 비밀번호**(내 구글 시트) 또는 **선생님 열쇠**(체험 서버)가 있어야 해요.
- `@OnlyCurrentDoc` 설정으로 서버 코드는 연결된 시트 하나에만 접근해요.
- 내 구글 시트: 게임 진행 정보와 사진은 7일 뒤 정리되고, 질문 기록은 선생님이 지우기 전까지 남아요. 결과 화면의 **게임 정리하기**에서 질문 기록까지 지울 수도 있어요.

## 알려진 한계

- Apps Script는 응답이 1~3초쯤 걸려요. 그래서 시작·멈춤·발표 신호가 태블릿에 닿는 데 2~5초 걸릴 수 있어요. 차례 넘기기와 칸 붙이기는 태블릿 안에서 바로 돼요.
- Apps Script 무료 한도는 **계정마다** 계산돼요. 체험 서버는 모든 학교가 개발진 계정 하나를 함께 쓰므로, 같은 시간에 수업하는 반이 많으면(대략 20반 안팎부터) 느려지거나 "요청이 몰렸어요" 안내가 나올 수 있어요. 자주 읽는 정보는 캐시에 담아 스크립트 속성 하루 한도(5만 번)는 거의 쓰지 않도록 했어요.
- 학교 업무용 Google Workspace 계정은 관리자가 "모든 사용자" 웹 앱 배포를 막아 두었을 수 있어요. 개인 Gmail을 권해요.
- 웹 글꼴은 자주 쓰는 한글 2,350자만 담았어요. 드문 글자는 기기 기본 글꼴로 보여요.
